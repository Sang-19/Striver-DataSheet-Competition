# FIREBASE SETUP — STRIVER ARENA

This project uses Firebase Authentication and Cloud Firestore. It uses Vite to read Firebase Web App configuration from environment variables at build time.

## 1. Create a Firebase project and Web App
1. Open https://console.firebase.google.com/ and select your project.
2. In Project Overview, register a Web App (</>) named Striver Arena.
3. Open Project settings → General → Your apps and copy the Firebase config values.

## 2. Add Vercel environment variables
In Vercel:
1. Open your Striver Arena project → Settings → Environment Variables.
2. Add these six variables. Use the matching values from Firebase Web App config:
   - VITE_FIREBASE_API_KEY = apiKey
   - VITE_FIREBASE_AUTH_DOMAIN = authDomain
   - VITE_FIREBASE_PROJECT_ID = projectId
   - VITE_FIREBASE_STORAGE_BUCKET = storageBucket
   - VITE_FIREBASE_MESSAGING_SENDER_ID = messagingSenderId
   - VITE_FIREBASE_APP_ID = appId
3. Select Production and Preview (and Development if desired).
4. Save, then trigger a new deployment. Environment variable changes do not update an already-built deployment.
5. For local development, copy .env.example to .env.local and fill in the same values. Do not commit .env.local.

IMPORTANT: VITE_* variables are compiled into browser JavaScript. They are not secret storage. Firebase Web App config is public client configuration. Never put service-account JSON, Admin SDK credentials, private keys, or OAuth client secrets in VITE_* variables.

## 3. Restrict the Firebase API key
1. Open https://console.cloud.google.com/apis/credentials.
2. Select the API key associated with the Firebase Web App.
3. Under Application restrictions, choose Websites (HTTP referrers).
4. Add your production hostname, e.g. https://YOUR-PROJECT.vercel.app/* and any custom domain.
5. Add localhost referrers only if needed for local testing.
6. Save. Check Firebase/Google API requirements before restricting APIs; do not block APIs required by Firebase Authentication or Firestore.

API key restrictions reduce misuse but are not a substitute for Firebase Security Rules.

## 4. Enable Authentication
1. Firebase Console → Build → Authentication → Get started.
2. Sign-in method → enable Email/Password.
3. Enable Google and choose a support email.
4. Authentication → Settings → Authorized domains: add localhost and your Vercel production/custom domains.

## 5. Create Cloud Firestore
1. Firebase Console → Build → Firestore Database → Create database.
2. Choose Production mode and a region close to your users (for example asia-south1 if available).
3. Create the database.

## 6. Publish Firestore rules
1. Open Firestore Database → Rules.
2. Copy the complete contents of firestore.rules from this repository.
3. Paste and click Publish.
4. Never use open rules such as allow read, write: if true in production.

Collections used:
- users/{uid}: profile and aggregate progress fields
- users/{uid}/progress/{taskId}: per-user manual completion status and timestamps
- competitions/{competitionId}: competition name, invite code, owner and member UIDs
- competitions/{competitionId}/members/{uid}: member summary
- inviteCodes/{code}: invite-code lookup

Firestore creates collections/documents on first write; do not create them manually.

## 7. Local run and Vercel deployment
Local:
1. npm install
2. Copy .env.example to .env.local and fill values.
3. npm run dev

Vercel:
1. Import the repository and select the branch containing this Vite migration.
2. Framework preset: Vite; Build command: npm run build; Output directory: dist.
3. Add the six VITE_FIREBASE_* variables in Project Settings → Environment Variables.
4. Redeploy.
5. Add the deployed domain to Firebase Authentication → Authorized domains and to the API key HTTP referrer restrictions.

## 8. Security and production notes
- Firebase Web API keys identify the project; they do not grant Firestore access by themselves. Auth and Firestore Rules enforce access.
- All VITE_* values are public in the browser bundle. Do not use them for secrets.
- Never expose service-account keys or Admin SDK credentials.
- The current competition invite flow is a client-side MVP. For production anti-cheat, rate limiting, unique invite code generation, and trusted scoring, implement Cloud Functions and validate writes server-side.
- Monitor Firestore usage and billing in Firebase Console.
